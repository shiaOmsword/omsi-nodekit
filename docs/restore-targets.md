# Восстановление SQLite в выбранное окружение

SQLite-бэкап 3x-ui содержит базу панели, а не способ установки исходного
процесса. Native → Docker + Caddy — нормальный сценарий восстановления;
ставить такую же ОС, systemd unit или старый Caddyfile не требуется.

## Порядок

1. Настроить SSH новой пустой VPS и выполнить обнаружение. Работающая
   сторонняя панель или непустой управляемый каталог не заменяются.
2. В операции **Восстановление** выбрать загруженный `.db` или `.nodekit.zip`.
3. Открыть параметры установки/восстановления с выбранным бэкапом. Мастер
   читает только пути `webBasePath` и `subPath`, с проверкой SQLite/checksum.
   При отсутствии значений учитываются прежние defaults 3x-ui.
4. Выбрать окружение назначения. Для новых конфигураций предлагается
   **Docker + Caddy**; native/systemd, native + Caddy и отсутствие Caddy
   остаются явными вариантами. Если Caddy уже есть, выбрать именно его,
   чтобы сохранить чужие сайты. Установку Docker при отсутствии разрешить
   отдельной отметкой. Существующие явно заданные профили не меняются молча;
   кнопка рекомендуемого варианта позволяет выбрать Docker + Caddy заново.
5. Сохранить параметры, проверить домен, целевые порты, пути и план, запустить.
   При несовпадении путей выбранного бэкапа и YAML ошибка показывается до SSH
   задания. Проверка повторяется перед постановкой задания; удалённая проверка
   путей при восстановлении тоже сохраняется.

| Параметры | Поведение |
| --- | --- |
| Панель Docker/native, Caddy, домен, порты и private bind | Из параметров назначения |
| Пути панели и подписок | Из выбранной SQLite, для совместимости ссылок |
| Пользователи 3x-ui, inbound, клиентские UUID/subId и WG-идентичности | Из исходной базы |
| ОС, старые systemd units, raw Caddy, интерфейсы и firewall defaults | Не копируются как инфраструктура назначения |

Версия 3x-ui должна быть совместима с базой; выбор Docker сам по себе не
конвертирует произвольный старый формат. При переносе следует сохранять
исходную SQLite отдельно. Публичные домены/публикации и WG Endpoint/DNS требуют
проверки: сохранение ключа не меняет DNS и настройки уже импортированного клиента.

Архив `.nodekit.zip` дополнительно содержит переносимые системные настройки
и материалы восстановления. **Восстановить настройки ноды** и восстановить
саму панель из SQLite — разные операции. SSH-ключи восстанавливаются только
при совпадении логического node id и профиля туннеля; raw файлы сохраняются
для справки. См. [системные бэкапы](system-backups.md).

Локальная проба использует один и тот же SQLite snapshot для native,
native + Docker Caddy и Docker + Caddy. Проверяется смена private listeners
и портов без изменения таблиц пользователей, inbound/WG identities и путей.
Это не заменяет запуск конкретной версии 3x-ui с реальным бэкапом на новой VPS.
