# Бэкап и восстановление параметров ноды

**Нода → Операции → Бэкап ноды** создаёт `.nodekit.zip` в существующем
хранилище бэкапов. Состав версии 1:

- `x-ui.db`: согласованный SQLite snapshot. Здесь же остаются серверные WG
  ключи, сохранённые клиентские private/public keys, PSK и адреса peers.
- `system.json`: конфигурация Nodekit без sudo-пароля, фактический TCP
  алгоритм BBR/CUBIC, ключи и known_hosts настроенных SSH-туннелей; собственные
  manifest, Compose/Caddy site, inbound/host/firewall и tunnel/pool metadata
  сохраняются как справочные данные.
- `manifest.json`: версия формата и SHA256 двух предыдущих файлов.

Архив приватный и **не зашифрован**: он содержит ключи. Права хранения
наследуются от существующего PrivateFiles. Контрольные суммы обнаруживают
повреждение, но не удостоверяют доверенность источника. Лимит размера один
для архива и его распакованного содержимого. Неизвестные/дублированные пути,
symlink entries, неверная версия и checksum отклоняются. Распаковки произвольных
путей на диск нет. Старые `.db` остаются полностью совместимыми.

## Перенос

1. Сохранить конфигурацию с прежним логическим `id`, новым SSH-адресом и
   проверенными для новой VPS параметрами deployment/Caddy. Локальный ключ
   управления новой VPS выбрать отдельно. Пользователи SSH-туннелей должны
   существовать на целевой VPS.
2. Обнаружить новую VPS. **Операции → Восстановить настройки ноды**: выбрать
   `.nodekit.zip` и посмотреть план. Он показывает исходный TCP-алгоритм и имена
   сохранённых туннелей. Перед записью повторно проверяется fingerprint TCP.
3. Восстановление применяет TCP через существующий TCPConfigurator и создаёт
   отсутствующие ключи/known_hosts по **целевым путям** текущего YAML, с правами
   0600 и владельцем соответствующего пользователя. Нужны совпадающие имя,
   host, user и SSH port туннеля. Чужие/отличающиеся файлы и symlinks вызывают
   отказ до изменений. При ошибке выполняется откат собственных изменений.
4. Обычное **Восстановление** из этого же ZIP извлекает только проверенную БД
   и разворачивает панель штатным сценарием; ключи уже доступны для SSH.
5. Повторить обнаружение/диагностику, настроить Caddy штатным механизмом
   выбранной новой установки, проверить подписки и внешний клиент. При
   повторном запуске восстановления настроек после установки UFW согласуется
   с текущей целевой конфигурацией; до установки UFW не меняется.

## Граница автоматизации

Это восстановление поддерживаемых параметров Nodekit, а не образ ОС.
Исходные IP, Docker bridge/interface names, default routes, произвольные sysctl,
UFW default policies, SSHD и общий Caddy не копируются на новую машину.
Справочные файлы не устанавливаются вслепую: raw Caddy upstream и ownership
старой установки могут не соответствовать новой VPS. Маршруты и сервисы
воссоздаются существующими действиями панели с конфигурацией назначения.
Сертификаты общего Caddy и ключ локального управления VPS в архив не входят.

Ветки WireGuard и сетевой диагностики независимы от этой ветки. Их новые
настройки можно включить в следующую версию формата после объединения.
Новые автоматические тесты оставлены отдельному этапу; существующий CI и
изолированная проверка archive/import/DB-extraction выполняются сейчас.
