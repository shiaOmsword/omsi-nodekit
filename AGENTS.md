# Рабочий процесс

- Вести изменение в отдельной ветке от `dev` и одном PR. Не сливать PR без
  соответствующего поручения пользователя.
- Делать несколько осмысленных коммитов по завершённым частям, а не один
  большой в конце. Пушить проверенные этапы, чтобы сбой чата не потерял работу.
- Сохранять принятые конфигурации и инструкции в `docs/`, без секретов.
  При восстановлении сначала сверять удалённый HEAD, коммиты PR и CI;
  продолжать существующую работу, не начинать её заново.
- Продолжать задачу в одном чате. Самостоятельно выполнять понятные шаги;
  обращаться к пользователю при существенной проблеме или нехватке данных.
- В конце проверять итоговый diff, подходящие тесты, сборку и CI именно
  окончательного HEAD. Не объявлять проверки успешными до получения результата.
- При красном CI сначала читать логи и отличать ошибку кода от сбоя GitHub.
  Ошибки кода исправлять до перехода к тестированию на живой VPS.
  Инфраструктурный сбой GitHub допускает такой переход в пределах текущего
  разрешения пользователя; явно указывать, что осталось непроверенным.
